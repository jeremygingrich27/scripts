## 1. Prerequisites & Environment Setup

### 1.1 TACC Lonestar6 Modules

All VASP jobs load the following modules (handled automatically by generated jobscripts):

```bash
module purge
module load intel/19.1.1  impi/19.0.9
module load vasp/6.3.0
export OMP_NUM_THREADS=1
```

Phonopy post-processing jobs instead load:

```bash
module purge
module load gcc/13.2.0   # phonopy's Python dependencies require a newer GCC
```

### 1.2 Conda Environments

A dedicated conda environment is used for phonopy and related Python tools.

```bash
source /work/10117/jerging27/ls6/anaconda3/etc/profile.d/conda.sh
conda activate phonopy
export LD_LIBRARY_PATH="/work/10117/jerging27/ls6/anaconda3/lib:$LD_LIBRARY_PATH"
```

The `phonopy` environment contains: `phonopy`, `sumo`, `easyunfold`, and their dependencies.

### 1.3 Required External Tools

| Tool | Purpose | Called by |
|------|---------|-----------|
| `vasp_std` | DFT total energy / forces | all job scripts |
| `vaspkit` | K-point generation, elastic analysis, DOS | `setup_system.sh`, `elastic/setup.sh`, `fd_phonons_job.sh` |
| `phonopy` | Finite-displacement phonons, force constants | `fd_phonons_job.sh`, `phonopy` snippet |
| `sumo` (`sumo-kgen`) | High-symmetry k-path generation for band structures | manually or in band unfolding setup |
| `easyunfold` | Band unfolding from supercell to primitive cell | band unfolding workflow |

### 1.4 Expected Directory Structure

Scripts assume the following layout under `$HOME`:

```
~/
├── scripts/           ← this repository (scripts/scripts/)
├── POSCARs/           ← one file per system, named by system label
│   ├── SrTiO3
│   ├── CuO
│   └── ...
└── input_files/
    └── vaspkit/
        └── elastic_INPUT.in   ← vaspkit template for elastic setup
```

`crystal_system_directory_setup.sh` reads `~/POSCARs/<SYSTEM>` to bootstrap a new project.

### 1.5 vaspkit Configuration

`crystal_system_directory_setup.sh` writes a pseudopotential-specific vaspkit config:

```bash
sed "s/PSEUDO/$PSEUDO/" ~/.vaspkitbase > ~/.vaspkit
```

Make sure `~/.vaspkitbase` exists and contains a `PSEUDO` placeholder for the
pseudopotential path you want to swap in.

## 2. Project Directory Setup

### Why

Starting every project from a consistent skeleton prevents the common mistake of
running calculations in an unorganized flat directory, makes it easy to hand off
work to collaborators, and ensures vaspkit generates symmetry information and KPOINTS
for the unrelaxed structure before anything changes.

### How

```bash
bash ~/scripts/util/crystal_system_directory_setup.sh <SYSTEM> <PSEUDO> <KPR> <KSCHEME> <DIRNAME>

# Example: monoclinic CuO with PBEsol pseudopotentials
bash ~/scripts/util/crystal_system_directory_setup.sh CuO PBEsol 0.04 2 CuO_study
```

**Arguments:**

| Arg | Description | Example |
|-----|-------------|---------|
| `SYSTEM` | Label matching a file in `~/POSCARs/` | `CuO` |
| `PSEUDO` | Pseudopotential family for vaspkit config | `PBEsol` |
| `KPR` | K-point resolution (Å⁻¹ per reciprocal lattice vector) | `0.04` |
| `KSCHEME` | vaspkit K-scheme code (1=Γ-centered, 2=Monkhorst-Pack) | `2` |
| `DIRNAME` | Name of the project directory to create | `CuO_study` |

**What it creates:**

```
CuO_study/
├── POTCAR
├── unrelaxedPOSCAR
├── unrelaxedSymmetry     ← vaspkit symmetry analysis of starting structure
├── README                ← vaspkit structure summary
├── electrons/
│   └── POTCAR
├── elastic/
│   └── POTCAR
├── phonons/
│   └── POTCAR
└── relax/
    ├── POSCAR
    ├── POTCAR
    └── KPOINTS           ← generated by vaspkit
```

## 3. Workflow A — Structural Relaxation → Electronic Structure

### Why

Before computing any property, the structure must be relaxed to its ground-state
geometry. VASP's `NSW` tag limits relaxation to a fixed number of ionic steps per
run; for systems that need many steps (low-symmetry, magnetic, strongly correlated),
a single run is rarely enough. `repeat_relax.sh` automates re-running VASP and
updating `POSCAR ← CONTCAR` until the structure stops changing, providing a
robust stopping criterion independent of `NSW`.

Once relaxed, the charge density from a self-consistent (SCF) calculation is used
as a fixed input (`ICHARG=11`) for the non-self-consistent (NSCF) band structure
calculation. This is the standard two-step approach: the charge density encodes
the electronic ground state, and the NSCF step evaluates eigenvalues on the desired
k-path without altering it.

### Step-by-step

#### Step 1 — Prepare input files

Place `relax_INCAR`, `POSCAR`, `POTCAR`, and `KPOINTS` in the project root
(or use the skeleton from §2 which already has them in `relax/`).

```bash
cd CuO_study/relax/
```

If you need to create the `relax/` directory manually:

```bash
bash ~/scripts/structure/relax/setup.sh input_files/
```

#### Step 2 — Write and submit the relaxation jobscript

```bash
bash ~/scripts/jobs/write_jobscript.sh
```

When prompted for optional snippet additions, select:
- `converged_structural_relaxation` — embeds the full iterative relaxation loop

This generates a `jobscript` that:
1. Detects any previous partial relaxation and resumes from the last iteration
2. Runs VASP repeatedly (up to 50 iterations), copying `CONTCAR → POSCAR` each time
3. Stops when `|POSCAR - CONTCAR| < 1×10⁻⁸` Å (coordinate tolerance)
4. Backs up each iteration to `relaxation_outputs/iter_N/`
5. Logs energy, timing, and status to `relaxation.log`

```bash
sbatch jobscript
```

#### Step 3 — Check convergence

```bash
cat relax/relaxation.log
```

Look for `CONVERGED` in the final row. If the job hit the wall-clock limit before
converging, just resubmit — `repeat_relax.sh` resumes automatically.

You can also check manually:

```bash
bash ~/scripts/structure/relax/compare_poscar_2_contcar.sh 1e-6
# prints "true" if converged
```

#### Step 4 — SCF calculation for charge density

Copy the converged `CONTCAR` as the input for an SCF run in `electrons/`:

```bash
cp relax/CONTCAR electrons/POSCAR
cp relax/POTCAR  electrons/POTCAR
# place your SCF INCAR (ICHARG=2, ISTART=0, LWAVE=.TRUE., LCHARG=.TRUE.) and KPOINTS
```

Write and submit a jobscript (no snippet needed — just a plain `ibrun vasp_std`):

```bash
bash ~/scripts/jobs/write_jobscript.sh
sbatch jobscript
```

#### Step 5 — NSCF band structure

Place your band-path `KPOINTS` in a new directory (e.g. `electrons/bands/`),
copy `CHGCAR` and `WAVECAR` from the SCF run, and set `ICHARG=11`, `ISTART=1`
in the INCAR. Submit as a normal VASP job.

**Why ICHARG=11?** It tells VASP to read the charge density from `CHGCAR` and
keep it fixed throughout — no self-consistency is performed. This is ~10× faster
than SCF and gives eigenvalues on a dense k-path without distorting the ground-state
density.

## 4. Workflow B — Phonons (Finite Displacement)

### Why

The finite-displacement (FD) method computes the force-constant matrix by
displacing each symmetry-inequivalent atom by a small amount (typically 0.01–0.03 Å)
and running a static VASP calculation to get the Hellmann-Feynman forces. Phonopy
then constructs the dynamical matrix and diagonalizes it to get phonon frequencies
and eigenvectors. FD is preferred over DFPT for systems with Hubbard U corrections
or hybrid functionals, where DFPT is not readily available.

A supercell is used so that the force constants decay to zero within the cell
boundaries, satisfying the periodic boundary condition assumption of the dynamical
matrix.

### Step-by-step

#### Step 1 — Set up the phonons directory from relaxation

```bash
# Run from the project root (parent of relax/)
# Requires phonons_INCAR in the current directory
bash ~/scripts/structure/phonons/after_relax.sh
```

This copies `relax/CONTCAR → phonons/POSCAR` and brings over `POTCAR`, `CHGCAR`,
and `WAVECAR`. The `CHGCAR` provides a starting charge density so the static
displacement calculations converge faster.

#### Step 2 — Generate displacement supercells

```bash
cd phonons/
bash ~/scripts/structure/phonons/make_disp_line_arg.sh
# Optionally copy extra files, e.g.:
bash ~/scripts/structure/phonons/make_disp_line_arg.sh --cp CHGCAR
```

This runs `phonopy -d` to create the displaced POSCARs and organizes them into
numbered subdirectories (`001/`, `002/`, ...) each with `INCAR`, `KPOINTS`, `POTCAR`.

**Why multiple displacement directories?** Each symmetry-inequivalent atom requires
its own displacement (and each direction, though phonopy reduces these by symmetry).
They are independent calculations that can run in parallel.

#### Step 3 — Submit the force-constant job

```bash
bash ~/scripts/structure/phonons/fd_phonons_job.sh -n 1 -c 128 -t 24:00:00
```

This generates and submits a single SLURM job that:
1. Runs `ibrun vasp_std` in each `00N/` displacement directory sequentially
2. Calls `phonopy -f 00*/vasprun.xml` to extract forces and build `FORCE_SETS`

**For multiple structures (batch):**

```bash
bash ~/scripts/structure/phonons/batch_fd_jobs.sh
```

#### Step 4 — Post-process with phonopy

After the job completes, activate the phonopy conda environment and run the
`phonopy` snippet or manually:

```bash
source /work/10117/jerging27/ls6/anaconda3/etc/profile.d/conda.sh
conda activate phonopy

# Generate k-path
echo -e "305\n3" | vaspkit    # writes KPATH.phonopy

# Edit KPATH.phonopy as needed (DIM, MP, PRIMITIVE_AXES)
sed -i '/^DIM/s/.*/DIM = 1 1 1/' KPATH.phonopy
sed -i '/^MP =/s/.*/MP = 20 20 20/' KPATH.phonopy
echo "PRIMITIVE_AXES = AUTO" >> KPATH.phonopy

# Compute and plot band structure
phonopy --readfc KPATH.phonopy -p -s
```

This produces `band.yaml` and a `band.pdf` plot.

## 5. Workflow C — Elastic Constants

### Why

The elastic constant tensor C_ij is computed by applying a set of small strains to
the relaxed unit cell and measuring the resulting stress tensor. Vaspkit generates
the required strain matrices (based on the crystal symmetry) and analyzes the
stress–strain response after VASP runs. The eigenvalues of C_ij determine mechanical
stability (Born criteria).

### Step-by-step

#### Step 1 — Generate strain matrices

```bash
cd elastic/
cp ../relax/CONTCAR POSCAR   # use the fully relaxed structure
bash ~/scripts/structure/elastic/setup.sh
```

This calls vaspkit (option 02 → 201) and generates `strain_*/` subdirectories,
each containing a strained POSCAR.

#### Step 2 — Distribute input files

```bash
bash ~/scripts/structure/elastic/distribute_inputs.sh
# Default: symlinks INCAR, KPOINTS, POTCAR into every strain_*/
```

Use a tight EDIFF (≤1×10⁻⁸) and a static INCAR (`NSW=0`, `IBRION=-1`) —
you want accurate stresses, not ionic relaxation.

#### Step 3 — Submit jobs

```bash
bash ~/scripts/jobs/elastic_vaspkit.sh
```

Submits a VASP job for each `strain_*/` directory across all top-level directories.

#### Step 4 — Analyze

```bash
bash ~/scripts/structure/elastic/analysis.sh
# Run from within a completed strain directory; writes ELASTIC_INFO
```

For a batch of scaled structures:

```bash
bash ~/scripts/structure/elastic/scaled_analysis.sh
bash ~/scripts/structure/elastic/collect_info.sh
```

`collect_info.sh` aggregates all `ELASTIC_INFO` files and extracts eigenvalue
stability results into a single summary.

## 6. Workflow D — Lattice Parameter Sweep

### Why

To map out the energy landscape as a function of lattice parameters (e.g., the
equation of state, c/a ratio effects, or strain along a specific axis), a sweep
of scaled POSCARs is run. Each scaled structure gets a separate static VASP
calculation. The results are then parsed into a table for fitting or plotting.

This is the standard approach for finding the DFT-predicted equilibrium lattice
constant when a full variable-cell relaxation (ISIF=3) is unreliable (e.g., for
antiferromagnets where cell symmetry can break unexpectedly).

### Step-by-step

#### Step 1 — Generate scaled POSCARs

For an isotropic volume sweep:

```bash
python3 ~/scripts/structure/editor/poscar_scaler.py POSCAR multiple \
    0.95 0.95 0.95  1.05 1.05 1.05  0.01 0.01 0.01
# xmin ymin zmin  xmax ymax zmax  dx dy dz
```

For a c/a sweep at constant volume:

```bash
python3 ~/scripts/structure/editor/ca_ratio_volume_constant.py POSCAR ratios.txt
# ratios.txt: one c/a value per line
```

For an anisotropic sweep decoupling in-plane (xy) and out-of-plane (z):

```bash
bash ~/scripts/structure/editor/setup_varied_scale_factors.sh -xy 0.95:1.05:0.01 -z 0.95:1.05:0.01
```

#### Step 2 — Build the calculation tree

```bash
bash ~/scripts/structure/scaled/setup_system.sh <SYS> <CALC> <KPR> <KSCHEME> <FUNCTIONAL>

# Example
bash ~/scripts/structure/scaled/setup_system.sh CuO scf 0.04 2 PBEsol+U
```

This creates `PBEsol+U/scf/POSCAR_scaled_*/` directories, each with a `POSCAR`
and a vaspkit-generated `KPOINTS`.

#### Step 3 — Submit the chain job

```bash
bash ~/scripts/jobs/scaled_batch_basic.sh
```

This submits a single SLURM job that runs VASP in each `POSCAR_scaled_*/`
directory in sequence, then calls `data_parser.sh` automatically at the end.

To chain calculations with `CHGCAR` or `WAVECAR` carried forward (useful for
converging magnetic states across the sweep):

```bash
bash ~/scripts/jobs/write_chain_vasp_jobscript.sh
# Prompts let you select which directories to chain and which files to copy forward
```

#### Step 4 — Parse results

```bash
cd PBEsol+U/scf/
bash ~/scripts/structure/scaled/data_parser.sh
```

Output files in `PBEsol+U_scf/`:

| File | Contents |
|------|----------|
| `energies.dat` | dir, a, b, c (Å), E (eV) |
| `electronic_band.dat` | dir, a, b, c, gap (eV), Fermi (eV) |
| `magnetization.dat` | per-atom magnetization blocks |
| `atom_counts.dat` | species counts per directory |
| `convergence_summary.txt` | pass/fail count |

Use `--relax` to also check ionic convergence from OSZICAR:

```bash
bash ~/scripts/structure/scaled/data_parser.sh --relax
```

## 7. Workflow E — Band Unfolding (easyunfold)

### Why

When a magnetic or structural ordering doubles (or quadruples) the unit cell,
the electronic band structure is computed in the reduced Brillouin zone of the
supercell. Band unfolding maps these supercell eigenvalues back onto the Brillouin
zone of the primitive (chemical or magnetic) cell using spectral weights, recovering
a band structure that can be compared to experiments (ARPES, optical spectra) and
to primitive-cell calculations.

Two primitive cells are typically of interest:
- **Chemical primitive**: the smallest cell consistent with the atomic species
  (ignores spin ordering). Useful for comparison to paramagnetic measurements.
- **Magnetic primitive**: the smallest cell consistent with the magnetic ordering.
  Useful for identifying zone-folding artifacts introduced by the magnetic supercell.

`LWAVE=.TRUE.` is required in the INCAR because easyunfold reads the WAVECAR
to compute the spectral weight of each supercell eigenstate in the primitive BZ.

### Prerequisites

- A converged supercell SCF calculation providing `CHGCAR`
- The supercell `POSCAR` and the primitive `POSCAR_primitive` for each unfolding target
- easyunfold installed in the `phonopy` conda environment

### Step-by-step

#### Step 1 — Generate the unfolded k-path

In each unfolding directory (e.g. `chemical_primitive/`, `magnetic_primitive/`):

```bash
conda activate phonopy

# Generate the supercell k-path that unfolds to the primitive BZ path
easyunfold generate POSCAR_primitive POSCAR_supercell KPOINTS_band
# Writes easyunfold.json and KPOINTS_easyunfold
```

`KPOINTS_band` is the high-symmetry k-path in the **primitive** BZ
(generated by sumo-kgen or vaspkit). easyunfold folds each primitive k-point
back into the supercell BZ and writes the corresponding supercell KPOINTS.

#### Step 2 — NSCF calculation

Copy `CHGCAR` from the converged SCF run into the unfolding directory and set:

```
ISTART = 1
ICHARG = 11      # read charge density, do not update it
LWAVE  = .TRUE.  # write WAVECAR for easyunfold spectral weight extraction
LCHARG = .FALSE. # do not overwrite CHGCAR
```

Use `KPOINTS` = `KPOINTS_easyunfold` (the supercell k-path from Step 1).

Submit the job:

```bash
sbatch jobscript
```

#### Step 3 — Unfold

After VASP completes:

```bash
conda activate phonopy
easyunfold unfold --easyunfold easyunfold.json
easyunfold plot
```

This reads `WAVECAR` and `easyunfold.json` and produces the unfolded band
structure plot.

## 8. Utility Scripts

### Generating an INCAR from scratch

```bash
bash ~/scripts/util/generate_INCAR.sh
```

Reads `~/scripts/util/templates/INCAR.template`, lists available parameter blocks
(e.g. convergence, magnetism, LDA+U, output), prompts for values, and writes `INCAR`.
Useful when setting up a new calculation type for the first time.

### Generating a MAGMOM for coplanar orderings

```bash
# Equal sublattice moments (±M)
python3 ~/scripts/magnetism/coplanar_magnetic_atoms.py POSCAR [0,0,1] "Cu" 0.02 1 1.3

# Unequal sublattice moments (P and N)
python3 ~/scripts/magnetism/coplanar_magnetic_ordering.py POSCAR [0,0,1] "Cu" 0.02 1 1.3 -1.5
```

**Arguments:** POSCAR, normal vector to planes, element(s), coplanarity tolerance (Å),
planes per FM block, moment magnitude(s). Outputs a `MAGMOM` file ready to paste into INCAR.

### Timing and cleanup

```bash
# Sum all VASP elapsed times in subdirectories
bash ~/scripts/util/vasp_timer.sh

# Archive completed calculations (strips large files like WAVECAR/CHGCAR)
bash ~/scripts/util/collect_calcs.sh <dirname>

# Find and delete all WAVECARs (with confirmation)
bash ~/scripts/util/delete_WAVECAR.sh
```

### Convergence benchmarking

```bash
# Test ENCUT convergence
cd my_calc/
bash ~/scripts/util/benchmarks/bench_INCAR.sh
# Prompts: parameter = ENCUT, values = 400:600:50
```

Creates subdirectories `ENCUT_400/`, `ENCUT_450/`, etc. each with a complete
VASP input set. Submit with `submit_job_loop.sh` after writing jobscripts.

### Follow-up calculations

```bash
bash ~/scripts/util/batch_calcs/follow_up_calculations.sh
```

Sets up a new `CALC/` layer (e.g. `bands/`) on top of an existing set of
`POSCAR_scaled_*/` directories, optionally varying one or more INCAR parameters
across a grid (Cartesian product of parameter values).

## 9. Troubleshooting

### VASP fails immediately with "Error reading item 'MAGMOM'"

The number of values in `MAGMOM` must equal the total number of atoms in `POSCAR`.
Count: 32 Cu + 32 O = 64 atoms requires 64 MAGMOM entries.
Use the shorthand `32*1.3 32*0` to avoid counting errors.

### Relaxation never converges (hits 50-iteration limit)

1. Check `relaxation.log` — if energy is still dropping significantly each iteration,
   increase `NSW` in `relax_INCAR` and resubmit. The script will resume.
2. If the energy is oscillating, tighten `EDIFF` or add `ALGO = All` for systems
   with difficult electronic convergence (e.g. strongly correlated).
3. For magnetic systems, ensure `MAGMOM` is physically reasonable — wrong initial
   moments can trap the calculation in a metastable spin state.

### ICHARG=11 job fails with "charge density file not found"

`CHGCAR` must be present in the calculation directory. Copy it from the SCF run:

```bash
cp ../scf/CHGCAR .
```

Also verify `ISTART=1` is set — without it VASP ignores `ICHARG=11`.

### Phonon job produces imaginary frequencies

1. Check that the relaxation was fully converged before running phonons.
   Residual forces cause spurious imaginary modes.
2. Verify the supercell is large enough — force constants must decay to zero
   within the supercell. Try a larger `--dim` in phonopy.
3. Check for instabilities: if imaginary modes appear at zone-boundary k-points,
   the structure may be genuinely unstable (a true soft mode indicating a phase transition).

### easyunfold produces blank or garbled spectral weight plot

1. Confirm `LWAVE=.TRUE.` was set in the NSCF INCAR — without WAVECAR, easyunfold
   has nothing to read.
2. Confirm the correct `KPOINTS_easyunfold` was used as the VASP KPOINTS file —
   not `KPOINTS_band`.
3. Check `easyunfold.json` matches the current `POSCAR` and `POSCAR_primitive`
   — regenerate with `easyunfold generate` if the structures changed.

### data_parser.sh reports 0 converged calculations

The parser looks for `"General timing and accounting informations"` in `OUTCAR`
as the convergence sentinel. If VASP ran out of wall time before finishing,
this string will be absent. Re-run the job with a longer walltime.

Also check that you are running `data_parser.sh` from the `FUNC/CALC/` directory
level (the parent of `POSCAR_scaled_*/`), not from inside a scaled directory.

### Job exits with status 0 even though VASP failed

The `status=$?` in hand-written jobscripts must be placed immediately after
`ibrun vasp_std`. If it is placed before (a common copy-paste mistake),
it captures the exit code of the preceding command instead of VASP.
Use `write_jobscript.sh` to generate jobscripts rather than writing them by hand.

### COMPLETED sentinel prevents re-running a directory

`repeat_relax.sh` and chain job scripts skip directories that contain a `COMPLETED`
file. To force a directory to re-run:

```bash
rm <directory>/COMPLETED
```

### Module conflicts with phonopy conda environment

The phonopy conda environment requires `gcc/13.2.0`, not the Intel modules used
for VASP. Always do `module purge` before activating conda. Never mix the two
in the same job step.

## Common SLURM Defaults

| Parameter | Default |
|-----------|---------|
| Account | `PHY24018` |
| Queue | `normal` |
| Nodes | `1` |
| Cores | `128` |
| Walltime | `48:00:00` |
| VASP binary | `vasp_std` (VASP 6.3.0) |
| MPI stack | `intel/19.1.1 impi/19.0.9` |

All job-generating scripts prompt for these values and fall back to the defaults
above if you press Enter.
